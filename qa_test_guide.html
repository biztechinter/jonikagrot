01 Test Environment Setup & Pre-Configured Test Accounts

Before starting test execution, ensure the Next.js development server or staging instance is running. The application relies on server-side HTTP cookies for session persistence and file-based state storage in server-storage/db.json.

⚡ Quick Verification of Running Server
Run in terminal: curl -I http://localhost:3000. Verify that HTTP 200 OK is returned. If starting from cold, execute:
npm run dev # Starts Next.js development server on http://localhost:3000

02 Test Suite 1: Public Brand & Responsive Presentation

Validates brand aesthetics, typography hierarchy (Playfair Display serif headings and Plus Jakarta Sans body), responsiveness across viewports, and call-to-action routing.

TC-PUB-01 Homepage Hero & Brand Aesthetic (Desktop 1280px+) High
Preconditions: Browser opened in desktop resolution (1280x800 or wider).
  • Navigate to http://localhost:3000/.
  • Inspect the top navigation bar: verify logo, 6 main navigation items, and "Investor Access" CTA button.
  • Verify the luxury earth color palette: Deep Forest Evergreen (#16281E), Warm Earth Gold (#A88B65), Ivory (#FAFAF7).
  • Check the hero pill banner at the top of the hero text: "LAIKIPIA CONSERVANCY ECO-SYSTEM · PRIVATE ROUND".
  • Verify typography: Headings use Playfair Display serif; body text is clean sans-serif.
Expected Result: Page renders with zero horizontal scrollbar; typography is sharp and legibly spaced; buttons have smooth hover transitions (gold glow); hero imagery loads without layout shifts.
TC-PUB-02 Active Campaign Window Banner & Mobile Responsiveness (375px) Critical
Preconditions: Responsive mode set to 375px width (iPhone SE viewport).
  • Navigate to http://localhost:3000/.
  • Examine the top Campaign Window Banner ("ACTIVE DILIGENCE ROUND").
  • Verify that the banner remains in a clean single-row or neatly wrapped layout without text overlapping or badge clipping.
  • Verify the hero eyebrow pill text does not overflow or wrap awkwardly (uses compact 10px tracking).
  • Tap the hamburger navigation icon: verify the mobile drawer expands smoothly with full navigation links and close button.
Expected Result: Zero horizontal scrolling or layout breakages at 375px width; hamburger menu opens and closes cleanly; closing date and status badges remain readable.
TC-PUB-03 Tablet Viewport Layout & Investment Timetable Card (768px) Medium
Preconditions: Viewport set to 768px width (iPad portrait).
  • Navigate to http://localhost:3000/investment.
  • Scroll down to the Campaign Timetable Card.
  • Examine the status pills ("Active Diligence", "Closing Date", "Allocation Open").
  • Verify that none of the pill badges wrap their text onto two lines (protected with whitespace-nowrap).
  • Inspect the 4-column metric grid: verify it gracefully collapses to 2 columns without clipping card contents.
Expected Result: Responsive grid reflows naturally to 2 columns; all badges maintain intact padding and nowrap text.
TC-PUB-04 Public Inquiries & Contact Submission Form High
Preconditions: User is unauthenticated.
  • Navigate to the contact/inquiry section on /investment or /.
  • Attempt to submit with empty fields: verify HTML5 and custom client-side validation errors trigger.
  • Fill in valid details: Full Name: "Dr. Arthur Pendelton", Email: "arthur@capitalpartners.uk", Message: "Requesting conversation regarding Year 3 cash flow waterfall."
  • Click "Send Inquiry" button.
Expected Result: Button displays loading state; success toast/banner appears acknowledging submission; inquiry is written to db.json under inquiries array.

03 Test Suite 2: Investor Registration, Verification & Onboarding

Verifies the end-to-end journey of a prospective investor: registration form input validation, password strength enforcement, email verification, and session initiation.

TC-INV-01 Registration Form Field Validation & Accessibility Critical
Preconditions: Unauthenticated browser session.
  • Navigate to http://localhost:3000/investor-access.
  • Inspect form labels: click the label text for "Full Legal Name", "Business Email", and "Password". Verify that clicking the label correctly shifts browser focus to the associated input (confirms htmlFor/id pairing).
  • Enter an invalid email format (e.g. tester@domain without TLD) and short password (4 chars).
  • Click "Submit Access Request".
Expected Result: Submission is blocked; clear error messages indicate email format and minimum 8-character password requirement.
TC-INV-02 Complete New Investor Registration & Email Dispatch Critical
Preconditions: Form on /investor-access.
  • Fill valid registration details:
    • Full Legal Name: Sarah Jenkins, CFA
    • Business Email: sarah.jenkins.test@heritage-capital.com
    • Password: InvestorPass2026! (Confirm: InvestorPass2026!)
    • Organization: Heritage African Investments
    • Country: Kenya | Category: Institutional Investor
    • Investment Interest: Equity | Indicative Range: $500,000 – $1,000,000
    • Check the confidentiality and terms agreement checkbox.
  • Click "Submit Access Request".
  • Observe URL redirection to /login?verify=email&email=.... Verify that ?code=123456 is NOT present in the URL (security fix verification).
Expected Result: User is redirected to the verification screen; user record is created in server-storage/db.json with role: "registered" and emailVerified: false; random 6-digit verification code is generated.
TC-INV-03 Email Verification Code Submission (Dev Fallback & Failure Modes) Critical
Preconditions: On email verification prompt with email sarah.jenkins.test@heritage-capital.com.
  • Step A (Negative): Enter an incorrect 6-digit code: 999999 and click "Verify Email".
  • Verify error message: "Invalid verification code. Please check your email and try again." (Verify that no code hints are leaked in the error text).
  • Step B (Positive): Enter the test verification code: 123456 (or stored code) and submit.
  • Observe notification: "Email address verified successfully. Tier 2 portal access is now active."
Expected Result: Bad code is rejected with HTTP 400; valid code sets emailVerified: true in database, removes verificationCode from storage, and grants Tier 2 portal entry.
TC-INV-04 Unified Login Screen & Password Visibility Toggle Medium
Preconditions: Logged out. Navigate to http://localhost:3000/login.
  • Verify two sign-in options: "Sign in with Google" button and Email/Password credentials form.
  • Type password into the password field: verify characters are masked by default.
  • Click the "Show" eye icon: verify characters switch to visible plaintext.
  • Click "Hide": verify characters are masked again.

06 Test Suite 5: Security, Penetration & Vulnerability Testing

Verifies the application against unauthorized access, privilege escalation, credential leakage, API injection, brute-force attacks, and session tampering.

TC-SEC-01 Direct URL Route Protection (Middleware Guarding) Critical
Preconditions: Unauthenticated session (clear all cookies or use fresh incognito window).
  • Attempt to directly load: http://localhost:3000/portal.
    • Verify immediate 307/302 HTTP redirection to /login?redirect=%2Fportal.
  • Attempt to directly load: http://localhost:3000/admin.
    • Verify immediate redirection to /admin/login?redirect=%2Fadmin.
  • Attempt to directly load: http://localhost:3000/admin/investors.
    • Verify redirection to /admin/login.
  • Test open-redirect injection: load /login?redirect=https://evil.com. Log in. Verify user is redirected to /portal (safe default) and NOT to the external domain.
Expected Result: Middleware blocks unauthenticated access; open redirect exploits fail closed; only relative internal paths are honored.
TC-SEC-02 Direct API Access Protection & HTTP Status Enforcement Critical
Preconditions: Terminal / curl / Postman without authentication cookies.
  • Execute: curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/portal/documents
    • Verify returned HTTP status code is 401 (Unauthorized).
  • Execute: curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/portal/documents/doc-07/download
    • Verify returned HTTP status code is 401 (Unauthorized).
  • Execute: curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/admin/users
    • Verify returned HTTP status code is 403 (Forbidden).
Expected Result: All protected API endpoints return 401 or 403 when session cookie is absent; no JSON payload or document bytes are returned.
TC-SEC-03 Privilege Escalation: Tier 2 Requesting Tier 3 Document Download Critical
Preconditions: Authenticated as Tier 2 user (investor.registered@example.com).
  • Extract the active jonik_session_user cookie for the registered user.
  • Craft an authorized HTTP GET request targeting Tier 3 document doc-07:
    curl -H "Cookie: jonik_session_user=usr-registered" http://localhost:3000/api/portal/documents/doc-07/download
  • Inspect the response status and JSON body.
Expected Result: Server returns HTTP 403 Forbidden with message: "Access denied. This document requires Tier 3 Approved clearance." Download stream is strictly blocked.
TC-SEC-04 Zero Credential Exposure in JSON API Responses (Fix Verification) Critical
Preconditions: Authenticated as approved user or administrator.
  • Execute authenticated request to GET /api/portal/documents.
  • Inspect the user object in the returned JSON.
  • Verify that none of the following fields are present:
    • passwordHash: Must be undefined / omitted.
    • passwordSalt: Must be undefined / omitted.
    • verificationCode: Must be undefined / omitted.
  • Execute administrative user status update at POST /api/admin/users. Inspect returned user object: verify sensitive hashes are stripped.
Expected Result: API responses are sanitized; zero cryptographic salts, hashes, or verification tokens leak to browser memory or developer tools network tab.
TC-SEC-05 Brute-Force Attack Mitigation & Rate Limiting High
Preconditions: Automated script or repeated curl commands.
  • Execute 6 consecutive failed login attempts to POST /api/auth/login from the same IP with bad passwords within 1 minute.
  • Inspect the response to the 6th attempt.
  • Verify HTTP 429 Too Many Requests status.
  • Verify the response includes headers: Retry-After, X-RateLimit-Limit: 5, X-RateLimit-Remaining: 0.
Expected Result: 6th request is dropped with HTTP 429; application prevents automated password guessing.

07 Test Suite 6: Accessibility, Performance & UI Polish

Validates WCAG 2.1 AA accessibility conformance, screen reader landmarks, keyboard navigation focus indicators, touch targets, and motion preferences.

TC-UX-01 Keyboard Navigation & Accessible Focus Indicators High
Preconditions: Unauthenticated on http://localhost:3000/. Do not use mouse.
  • Press Tab repeatedly from the top of the page.
  • Verify skip-to-content link appears on initial tab press and shifts focus directly to main content area when activated with Enter.
  • Tab through navigation links: verify each active item displays a high-contrast 2px warm gold focus ring (#A88B65).
  • Navigate through the registration form on /investor-access using only Tab, Space, and Enter. Verify form can be fully completed and submitted without mouse interaction.
Expected Result: Complete keyboard accessibility; visible focus outlines on every interactive control; logical tab order matching visual layout.
TC-UX-02 Screen Reader ARIA Semantics & Landmarks Medium
Preconditions: Inspect DOM or enable Windows Narrator / ChromeVox.
  • Inspect the main navigation element in DevTools: verify aria-label="Primary navigation".
  • Inspect the mobile hamburger toggle button: verify presence of aria-expanded="false" (toggling to true when open) and aria-controls="mobile-nav-drawer".
  • Inspect mobile drawer container: verify id="mobile-nav-drawer" and role="navigation".
  • Inspect all <img> tags across homepage and investment page: verify descriptive alt text is present.
Expected Result: Accessibility tree reflects full structural semantics; assistive devices announce drawer expansion state and navigation context accurately.
TC-UX-03 Reduced Motion Accessibility Preference Low
Preconditions: Open DevTools Rendering tab, set Emulate CSS media feature prefers-reduced-motion: reduce.
  • Reload http://localhost:3000/.
  • Inspect floating badges, hero animations, and smooth transitions.
  • Verify all parallax, scale, and infinite keyframe animations are disabled or simplified to instant transitions.
Expected Result: Page renders statically without disorienting movement, honoring user vestibular preferences.

08 Defect Logging Protocol & Acceptance Sign-Off Matrix

Defect Severity Rubric

Severity Definition Examples Resolution SLA
Critical (P1) Security bypass, data leakage, crash, or broken primary revenue/onboarding flow. Password hash leak, unauthenticated document download, Tier 2 downloading Tier 3 doc. Immediate Blocker (Within 4 Hours)
High (P2) Major feature broken with no obvious workaround; significant layout breakdown. NDA execution failure, admin cannot approve investors, form validation failure. Fix before staging deployment (24 Hours)
Medium (P3) Minor functional issue or responsive flaw where a workaround exists. Badge wrapping on tablet, filter count discrepancy, slow query. Fix before next milestone sprint
Low (P4) Cosmetic defect, minor visual imperfection, typo, or minor styling nuance. Slight spacing inconsistency, subtle color variation. Backlog enhancement
